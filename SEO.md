## 1. Разбор конкурента wedwed.ru (31.08.2026, Firecrawl)

### Что у них в карте сайта

1227 URL, три ветки:

| Ветка | URL | Кол-во |
|---|---|---|
| Каталог Москвы | `/catalog/...` | ~591 |
| Каталог СПб | `/spb/catalog/...` | ~245 |
| Блог | `/article/<рубрика>/<slug>/` | **382 статьи** |

Рубрики блога и объём: `podgotovka-k-svad-be` 104, `vdohnovenie` 97,
`otnosheniya` 41, `den-svad-by` 37, `obraz-nevesty` 28, `trendy` 26,
`podryadchiki` 23, `znamenitosti` 15, `stil-zhizni` 11.

Статьи опубликованы 10.2025, `article:modified_time` — 05.2026:
**старые тексты регулярно переобновляют** (свежесть в Яндексе).

### Как устроены их посадочные каталога

Четыре оси, под каждую комбинацию — отдельный URL:

- **тип**: лофт, ресторан/банкетный зал, шатёр, усадьба/особняк, веранда, коттедж, загородный клуб, яхт-клуб;
- **вместимость**: 10–15, 20–25, 30–35, 40–45, 50–70, 80–120; лофты на 100/200/300;
- **гео**: округа Москвы (ВАО, ЗАО, САО, ЦАО, ЮАО…), Подмосковье; в СПб — районы (Приморский, Курортный, Адмиралтейский, Ленобласть);
- **повод**: свадьба / корпоратив / новогодний корпоратив / день рождения / фуршет — весь набор осей дублируется под каждый повод.

Плюс фильтры подрядчиков (`veduschie/na_15_chelovek`, `fotografy/nedorogo`)
и полная копия дерева под `/spb`.

### Главная находка

**Блог у них качает подборки-фильтры, а не карточки.** В теле статьи
6–10 контекстных ссылок точными анкорами, все — на страницы фильтров:

```
/spb/catalog/ploschadki/restoran-banketny-zal-dlya-svadbi/   анкор «банкетный зал»
/spb/catalog/ploschadki/usadba-osobnyak-dlya-svadby/         анкор «особняках»
/spb/catalog/ploschadki/restorany-kurortnyj/                 анкор «в Курортном районе»
/spb/catalog/ploschadki/loft-arenda/                         анкор «свадьбе в стиле лофт»
```

**А блок «WedWed рекомендует» под статьёй отдан подрядчикам** — ведущие,
фотографы, декор, кондитеры, стилисты. Площадок в нём нет даже под статьёй
целиком про выбор банкетного зала (проверено на двух статьях).
То есть конкретная площадка из блога не получает ничего.

**Связь односторонняя:** статья → фильтр. Карточка обратно на статьи не ссылается.

### Что из этого берём

| Их приём | Наше решение |
|---|---|
| 5–8 контекстных ссылок на подборки точными анкорами | обязательное правило статьи |
| Рубрика в URL, плоская структура | `/blog/<рубрика>/<slug>/` |
| Переобновление старых текстов | поля `published` / `updated` в данных статьи |
| Под статьёй — карточки подрядчиков | **у нас — карточки площадок** (их дыра) |
| Обратной связи нет | **у нас — блок «Читайте по теме» на карточке площадки** |

## 2. Наша схема перелинковки

```
блог (статья)
  ├─ 5–8 контекстных ссылок в тексте  →  подборка (посадочная-фильтр)
  ├─ блок «Площадки из этой статьи»   →  карточка площадки   ← перевес над конкурентом
  └─ блок «Читайте дальше»            →  соседние статьи

карточка площадки
  └─ блок «Читайте по теме»           →  статьи, где она упомянута   ← обратный вес
```

Носитель связи — данные, не вёрстка. В `src/data/articles.ts` у статьи два поля:

- `collections: { label, href }[]` — подборки, которые статья качает;
- `venues: string[]` — площадки, чьи карточки показываются под текстом.

Обратная выборка — `articlesAboutVenue(name)` в том же файле.

## 3. Типы статей, которые дают деньги

По убыванию коммерческого интента:

1. **«Ошибки при выборе X»** — прямой интент, ссылки на подборки естественны.
2. **«Свадьба на \<гео-объект\>»** (у конкурента — Финский залив). Гипотеза про
   Клязьму, Истру, Новую Ригу и округа Москвы **проверена Вордстатом 01.09.2026 и
   не подтвердилась**: 0–8 показов/мес. Гео-ось — «Москва» → «Подмосковье» →
   города МО (Красногорск, Мытищи, Одинцово, Химки). Подробно — [SEMANTICS.md](SEMANTICS.md).
3. **«Свадьба на N гостей»** — один-в-один мапится на подборки вместимости.
4. Чек-листы, бюджет, тайминг — трафиковые, денег почти не носят: держим меньшинством.

## 4. Что во фронте уже сделано (дизайн-прототип)

- Ссылка «Блог» в `SiteHeader`.

## 5. Сайт закрыт от индексации (снять перед запуском!)

Пока идёт дизайн-фаза, сайт живёт на своём домене, но закрыт от поисковиков —
сырые страницы, попавшие в индекс, потом висят в выдаче месяцами и портят
первое впечатление о домене. Закрыто в три слоя, снимается одним флагом:

| Слой | Где | Что делает |
| --- | --- | --- |
| `<meta name="robots" content="noindex, nofollow">` | `src/layouts/Layout.astro` | закрывает все HTML-страницы |
| `robots.txt` → `Disallow: /` | `src/pages/robots.txt.ts` | просит роботов не обходить сайт |
| `X-Robots-Tag: noindex, nofollow` | конфиг nginx на VPS | закрывает и не-HTML (картинки, PDF) |

**Как открыть индексацию в день запуска:**

1. В воркфлоу деплоя выставить `SITE_INDEXABLE=true` — снимутся мета-тег и `Disallow`.
2. На сервере убрать строку `add_header X-Robots-Tag` из конфига nginx, `nginx -t && systemctl reload nginx`.
3. Только после этого — добавлять сайт в Яндекс.Вебмастер и Search Console
   (см. скилл `yandex-webmaster`), иначе получим «страница запрещена в robots.txt».

## 6. Wordstat API: чем снимаем частотность (разбор 01.09.2026)

Старого отдельного API Вордстата (`api.wordstat.yandex.net` + OAuth) больше нет —
Wordstat переехал в **Yandex Cloud Search API v2** (тот же ключ, что у AI Studio).
Источник истины — proto-спека, а не гипертекст-документация:
[`wordstat_service.proto`](https://github.com/yandex-cloud/cloudapi/blob/master/yandex/cloud/searchapi/v2/wordstat_service.proto).

Корень: `https://searchapi.api.cloud.yandex.net/v2/wordstat/`,
заголовок `Authorization: Api-Key <ключ>`, **`folderId` обязателен в теле каждого запроса.**

| Метод | Путь | Что даёт нам |
| --- | --- | --- |
| `GetTop` | `/topRequests` | `totalCount` фразы за 30 дней + до 2000 похожих запросов (`results`) + ассоциации (`associations`) |
| `GetDynamics` | `/dynamics` | ряд `{date, count, share}` по дням/неделям/месяцам — сезонность |
| `GetRegionsDistribution` | `/regions` | распределение по регионам/городам + `affinityIndex` |
| `GetRegionsTree` | `/getRegionsTree` | справочник ID регионов (кэшируем один раз) |

Ограничения из proto: `phrase` ≤ 400 символов, `numPhrases` 1–2000,
`regions` ≤ 100 ID, `devices` ≤ 3 (`DEVICE_ALL/DESKTOP/PHONE/TABLET`).
Грабли: `count` приходит **строкой** (int64 → JSON string); `period` только
с префиксом (`PERIOD_MONTHLY`); для monthly `toDate` обязан быть последним днём
месяца; операторов `!`, `+`, `[]` в API нет — точную частотность снимаем руками
в веб-Вордстате.

Обвязка: `scripts/wordstat.mjs` (Node 22, без зависимостей), затравки —
`scripts/wordstat-seed.txt`, выгрузки — `scripts/wordstat-out/`.
Доступы лежат в `.env` (`WORDSTAT_API_KEY`, `WORDSTAT_FOLDER_ID`), файл в `.gitignore`.

```
node scripts/wordstat.mjs batch scripts/wordstat-seed.txt --regions 213,1 --num 500
```

**Ассоциации смотреть обязательно:** там всплывает другое написание того же
интента. У нас так и вышло: «свадебная площадка» — 4 648 показов/мес, а «банкетный
зал» — 41 027. Термин интерфейса и термин поиска разошлись.

Разбор снятого ядра, оси подборок, сезонность и пул статей — **[SEMANTICS.md](SEMANTICS.md)**.
Пересобрать ядро: `node scripts/wordstat.mjs batch … && node scripts/wordstat-clusters.mjs core-msk`.
