# Карта Яндекса — статус и следующие шаги

Рабочий документ на время эксперимента с картой. Удалить, когда карта
переедет в каталог площадок по-настоящему (см. пункт «Дальше» ниже).

## Что уже сделано

- `src/pages/karta-test.astro` — тестовая страница с картой и одной меткой
  (центр Москвы). Ключ не хранится в коде — читается из
  `import.meta.env.YANDEX_MAPS_API_KEY`.
- `.github/workflows/deploy.yml` — на шаге сборки прокидывает секрет
  `YANDEX_MAPS_API_KEY` в переменные окружения.
- Получены два ключа в кабинете разработчика (developer.tech.yandex.ru):
  - **API Геокодера** — переводит адрес в координаты (пригодится, когда
    будем проставлять гео подрядчикам в данных).
  - **JavaScript API** — рисует саму карту в браузере (нужен для этой
    тестовой страницы прямо сейчас).

## Шаг, который нужен от тебя в GitHub (чтобы карта заработала на сайте)

1. Репозиторий → Settings → Secrets and variables → Actions →
   New repository secret.
2. Имя: `YANDEX_MAPS_API_KEY`, значение — ключ пакета **«JavaScript API»**
   (не геокодера).
3. После этого обычный пуш в `master` соберёт сайт с этим ключом, и
   `/karta-test/` заработает на wed-secrets.ru.

## Как проверить у себя локально

Песочница этой сессии режет исходящие запросы к Яндексу — здесь карту
не увидеть даже с правильным ключом. Два рабочих варианта:

- **На реальном домене** — после того как секрет добавлен и код смержен
  в `master`, просто открыть `https://wed-secrets.ru/karta-test/`.
- **На своей машине**:
  1. `git pull` — забрать обновления;
  2. `npm install` (один раз, если ещё не ставили зависимости);
  3. в корне проекта создать файл `.env` (он в `.gitignore`, в репозиторий
     не попадёт):
     ```
     YANDEX_MAPS_API_KEY=<ключ JavaScript API>
     ```
  4. `npm run dev` и открыть `http://localhost:4321/karta-test/`.

## Дальше — когда переходим в каталог по-настоящему

Тестовая страница — только проверка, что ключ и подключение работают,
не финальная фича. В каталог площадок карта встанет, когда у подрядчиков
появятся реальные адреса:

1. Геокодировать адрес один раз при заведении карточки (API Геокодера),
   хранить `lat`/`lon` в данных площадки.
2. На странице каталога — `ymaps.Clusterer` вместо одиночной метки: одна
   площадка = одна метка, кластеризация сама схлопывает соседние на зуме
   (см. разбор конкурента в `SEO.md`).
3. `karta-test.astro` удалить — логика переедет в
   `src/pages/moskva/ploshchadki/index.astro`.
