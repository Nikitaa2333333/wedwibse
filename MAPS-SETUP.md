# Карта Яндекса — как устроена и что нужно помнить

Рабочий документ. Карта уже стоит в каталоге площадок, тестовая страница
осталась только для проверки меток без фильтров.

## Где карта живёт

- `src/components/VenueMap.astro` — сам модуль: метки, карточка по клику,
  ленивая загрузка API, повтор фильтрации каталога.
- `src/lib/map-points.ts` — сборка точек: координата из `venues.ts`,
  цена/фото/рейтинг из ленты `feed.ts`.
- `src/pages/moskva/ploshchadki/index.astro` — кнопка «На карте» / «Списком»
  в шапке раздела (слот `actions` у `ScopePicker`), карта подменяет мозаику.
- `src/pages/karta-test.astro` — та же карта, открытая сразу. **Временная**,
  удалить, когда карта в каталоге отработает.
- Стили метки и карточки — `.map-pin`, `.map-card` в `global.css`: разметку
  метки рисует JS карты, scoped-стили страницы туда не долетают.

## Четыре решения, которые не стоит переделывать заново

1. **Координаты — в данных, не геокодер в браузере.** `contacts.geo`
   (`{ lat, lon }`) у площадки. `ymaps.geocode` — отдельный API, отдельное
   право у ключа и лишний запрос на каждую загрузку; на этом карта уже один
   раз молча осталась без меток. Площадка без `geo` на карту не попадает.
   Адрес в точку переводим один раз руками при заведении карточки.
2. **Метка — не ссылка.** У неё задан `iconShape`, и клики забирает слой
   карты: `<a>` внутри макета их не увидит. Нажатие ловим событием метки:
   на ПК открывается карточка, на телефоне сразу переход на страницу.
3. **Карточки под картой рендерятся на сервере** и скрипт их только
   показывает — иначе фото пришлось бы собирать строкой мимо `astro:assets`
   (без сжатия и `srcset`).
4. **Скрипт Яндекса грузится лениво**, по первому показу карты
   (IntersectionObserver): пока в каталоге не нажали «На карте», страница не
   тянет ни килобайта чужого JS.

## Ключ

Читается из `import.meta.env.YANDEX_MAPS_API_KEY`, в коде текстом не лежит.
Секрет `YANDEX_MAPS_API_KEY` в GitHub → Settings → Secrets and variables →
Actions; `deploy.yml` прокидывает его на шаге сборки.

**Ограничение по HTTP Referer** в кабинете Яндекса (developer.tech.yandex.ru)
— главная причина «карта есть, а меток нет» или пустого серого блока: домена
нет в списке. Сейчас в ключе разрешены `wed-secrets.ru`, `www.wed-secrets.ru`,
`localhost` (плюс домены чужого проекта — ключ общий). Формат строгий: маски
`*.domain.ru` и голые IP (`127.0.0.1`) кабинет не принимает. Изменения
подхватываются не мгновенно — после сохранения подождать пару минут.

Локально открывать дев-сервер как `http://localhost:порт/`, а не по
`127.0.0.1`: для Яндекса это разные Referer.

**Долг:** ключ общий с посторонним проектом, лимит запросов у них один на
двоих. К моменту, когда карту начнут открывать посетители, завести
отдельный ключ под wed-secrets.

## Дальше

1. Проставить `geo` остальным площадкам — сейчас координаты есть у двух
   (Ривер Лофт, Лесная Роса), остальные на карту не выводятся.
2. `ymaps.Clusterer` со своим макетом капсулы: на десятках площадок метки
   слипнутся (у конкурента это «9+ от 56,9 млн», см. `SEO.md`).
3. Цена в метке — средний чек на гостя, а не аренда: на карте это читается
   двусмысленно. Появится поле аренды — показывать его.
4. Удалить `karta-test.astro`.
