# Конвейер контента — как материалы подрядчиков попадают на сайт

Каталог вырастет до сотен площадок и подрядчиков. Каждый отдаёт материалы
ссылкой на публичный Яндекс.Диск: сотни кадров вперемешку с баннерами,
дублями и браком, плюс ролики. Из этого нужно отобрать 30–50 кадров,
пережать и собрать посадочную страницу.

Этот документ — про то, **где** эта работа происходит и **почему не на ноутбуке**.
Про то, как страница устроена внутри, — `DESIGN.md` и скилл `venue-page`.

## Зачем понадобился сервер

Разработка идёт из России через VPN, иначе не работает Claude. Но в режиме
полного туннеля весь трафик уходит за границу, и выгрузка с Яндекс.Диска
ползёт со скоростью **4 Мбит/с**, а то и рвётся с `ConnectTimeoutError`.

Замер 29.09.2026 на одном и том же диске (392 МБ, 61 файл):

| Где | Время | Скорость |
| --- | --- | --- |
| Ноутбук через VPN | ~13 минут | 4 Мбит/с |
| VPS Timeweb (Россия) | **11 секунд** | 417 Мбит/с на роликах |

Разница стократная, потому что сервер стоит в России и ходит к Яндексу напрямую.
Материалы качает он, ноутбук в этом не участвует.

Про диагностику сетевых обрывов на самой машине — скилл `vpn-routing`.

## Что стоит на сервере (проверено 29.09.2026)

Сервер тот же, что отдаёт сайт: `193.124.47.78`, Ubuntu 26.04, 2 ядра,
1,9 ГБ RAM, 33 ГБ свободно. Вход — `ssh -i ~/.ssh/timeweb_wed root@193.124.47.78`.

| Что | Где |

Каталог **вне** `/var/www/wedsecrets` сознательно: деплой делает `rsync --delete`

## Инструмент: scripts/fetch-yadisk.mjs

Один скрипт на все выгрузки, в git. До 29.09.2026 вместо него было **25 разовых
скриптов** в `research/` плюс `scripts/yadisk-list.mjs` — и все они лежали вне
репозитория, потому что `research/` в `.gitignore`. Поэтому ни сервер, ни
облачная сессия их не видели.

```
node scripts/fetch-yadisk.mjs <url> <out>                    всё, рекурсивно
node scripts/fetch-yadisk.mjs <url> <out> --mode=list        показать, не качая
node scripts/fetch-yadisk.mjs <url> <out> --mode=preview     превью 600px + index.tsv
node scripts/fetch-yadisk.mjs <url> <out> --pick="004 005"   оригиналы отобранных

--only=photo|video   --jobs=6   --path=/подпапка
```

Токен Яндексу не нужен: работаем через публичный API по `public_key`.

Что важно знать про поведение:

- **Шесть параллельных загрузок** (`--jobs`). На медленном канале это главный
  выигрыш: последовательно соединение простаивало между файлами.
- **Докачка по размеру.** Файл того же размера второй раз не тянется, прогон
  можно прерывать и повторять.
- **Запись через `.part`** с переименованием — оборванная загрузка не встанет
  на место готовым файлом.
- **На 4xx кроме 429 падает сразу.** Мёртвая ссылка повтором не лечится, а пять
  заходов по нарастающей съедали минуту на каждом файле.

## Два скрипта: настройка и работа

Всё, что делается на сервере, запускается с ноутбука этими двумя. Руками по SSH
ходить не нужно.

**`scripts/research-setup.sh`** — разовая настройка сервера. Ставит Node,
создаёт каталоги, заливает загрузчик. Идемпотентный, гонять можно сколько
угодно. `--check` показывает, что стоит и сколько выгружено.

**`scripts/research.sh`** — повседневная работа:

```
bash scripts/research.sh list    <url>                 что на диске и сколько весит
bash scripts/research.sh preview <слаг> <url>          превью на сервер + к себе на отбор
bash scripts/research.sh pick    <слаг> "004 007 012"  оригиналы отобранных
bash scripts/research.sh all     <слаг> <url>          выкачать всё
bash scripts/research.sh pull    <слаг> [prev|raw]     забрать папку к себе
bash scripts/research.sh ls      [слаг]                что уже выгружено
```

Ссылка на диск запоминается при `preview` (файл `.url` рядом с превью), поэтому
`pick` вызывается без неё.

Оба запускать **из Git Bash**: Windows-ssh не принимает ключ `timeweb_wed`
из-за прав на файл — та же причина, что у `media-push.sh`.

Внутри каждый вызов SSH обёрнут в повтор: канал до сервера периодически рвётся
на рукопожатии (`kex_exchange_identification: Connection closed`), и без повторов
скрипт падал бы с первой попытки, хотя вторая-третья обычно проходят. Штатный
`ConnectionAttempts` здесь не помогает — он перезапускает только установку TCP.
Если не прошли все пять попыток, смотри скилл `vpn-routing`.

## Рабочий цикл: добавить подрядчика

```
1. Подрядчик прислал ссылку на публичный Диск
         ↓
2. Сервер: --mode=list        сколько там всего и какого объёма
         ↓
3. Сервер: --mode=preview     превью 600px + index.tsv «номер → путь»
         ↓
4. Отбор кадров: смотрим контактный лист, называем номера
         ↓
5. Сервер: --pick="004 007 012"   оригиналы отобранных
         ↓
6. Пережатие, вёрстка страницы, коммит
         ↓
7. GitHub Actions выкатывают сайт
```

Шаг 4 — единственный, где нужен человек: у отбора кадров есть вкус, и доверять
его целиком автоматике рано. Ради этого шага режимы `preview` и `pick` и
разведены: сначала дёшево тянем миниатюры, потом дорого — только выбранное.

## Где что лежит (важно для удалённой работы)

| Что | Объём | В git | На сервере |
| --- | --- | --- | --- |
| Отобранные кадры `src/assets` | 909 файлов | да | да |
| Ролики | 122 МБ | нет | да, `/var/www/wedsecrets-media` |
| Схема PocketBase `pb/pb_migrations` | 6 файлов | да | нет |
| Сырьё `research/` | 6,7 ГБ | нет | нет — только ноутбук |
| `ВЫБОРКА ФД/` | 107 МБ | нет | нет — только ноутбук |
| Данные PocketBase `pb/pb_data` | 551 МБ | нет | нет — только ноутбук |

**Сайт целиком живёт из git и с сервера** — то, что видит посетитель, не зависит
от ноутбука. Локальны только сырьё до отбора и база каталога.

Сырьё перевозить не надо: сервер перекачает его заново за секунды. А вот
`ВЫБОРКА ФД` и `pb_data` существуют в одном экземпляре — их надо сохранить.

## Что осталось сделать

1. **Claude Code на сервер** (`claude setup-token`, авторизация подпиской, не по
   API-ключу). Тогда задачу можно ставить с телефона, а качает, отбирает,
   верстает и коммитит сервер. Сейчас выгрузка запускается только руками по SSH.
2. **Поднять PocketBase на сервере.** Сейчас его там нет вообще — ни бинарника,
   ни данных, ни службы. Сайт статический и без него работает, но личный кабинет,
   CRM и монетизация из `AGENTS.md` упираются в эту базу. Пока она в единственном
   экземпляре на ноутбуке и вне git — это единственная точка отказа проекта.
3. **Сохранить уникальное** — `pb_data` и `ВЫБОРКА ФД`.
