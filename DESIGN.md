# Дизайн-система WED Secrets — текущее состояние

Правило — в токенах `src/styles/global.css`, «почему» — здесь. Общие законы
(токены, капс, жирность в наборе, мера строки, контраст) — в `AGENTS.md`,

## 1. Токены

| Группа | Токены и значения | Правило |
| --- | --- | --- |
| Бумага / чернила | образ «крем» на `<html data-look="cream">`: `--paper #f6efe5`, `--ink #45322a`, `--surface #ede4d7` (плашки), `--surface-dim #e5dacb` (подложка фото). Базовые белые значения в `:root` — запасной образ | Цветных заливок нет. `--accent #e8592a` — только логотип, ховер ссылки, отметка состояния |
| Шрифты | Onest — набор и всё служебное; Cormorant Garamond (`--font-serif`) — заголовки h1–h4 и крупные фразы | Антиква только крупно: мелким кеглем нечитаема. Имена в карточках, имена пунктов, метки — жирный Onest |
| Кегли | `--fs-display` 52–112, `--fs-h1` 34–64, `--fs-h2` 26–36, `--fs-h3` 21–26 (в «креме» 26–32), `--fs-lead` 20–26, `--fs-body` 18, `--fs-small` 16, `--fs-caption` 14 | Мельче `--fs-caption` нет. Поднял кегль — перепроверь `max-width` в `ch` |
| Вес | `--w-body 500 / --w-medium 600 / --w-head 600 / --w-head-lg 700` | Своих `font-weight` нет; крутить все четыре вместе |

## 2. Реестр элементов (global.css — ищем здесь, потом создаём)

- **`.pill`** — единственная кнопка-действие. **`.chip`** — плашка-выбор (фильтры, вкладки разделов; `.chip__count` — число в ней).
- **`.plates`** — короткие факты пилюлями россыпью (заливка `--surface`, без маркера). Только пункты в одну строку; длинные — `.list`.
- **`.list`** — единственный маркер списков (квадрат `--bullet-*`). Линий между пунктами нет нигде.
- **`.rows`** — строки «метка — значение». Один столбец по умолчанию; две колонки (`.rows--pairs`) ставит `rowsClass()` из `lib/rows.ts`, только если все пары короче 30 знаков. Линий нет; линии — только в таблице цен (`VenueTerms`, тариф зала).
- **`.shot`** — кадр внутри страницы карточки: 4:5, `--radius-card`, в полях страницы. Один вид у подрядчика (паузы между разделами, портрет) и площадки (сцены, залы). Слайдеров внутри страницы нет.
- **`.media` / `.media--bleed`** — кадр во всю ширину (первый экран). `PhotoRail` — единственный слайдер (первый экран, карточки каталога, доска).
- **`.sheet`** — нижняя шторка любой настройки (`lib/sheet.ts`); `--dock` на ПК — колонка слева.
- **`.theme-dark`** — инверсия секции (тон, не цвет).
- **`.hero-actions` / `.hero-btn`** — назад · избранное · поделиться поверх первого кадра; тонкий светлый ободок, чтобы не сливаться с тёмными секциями.
- **`.save`** — сердце на кадре (каталог площадок и подрядчиков), снимок общий с карточкой.
- **`<mark>`** — подложка `--mark` под тем же цветом текста. Используется в статьях; в карточках подрядчиков выделения нет (заказчик, 08.10).
- **`.veil` (затемнение фото) удалено** — текста на фото нет, затемнений нет нигде.

## 3. Страница подрядчика (`podryadchiki/[category]/[slug].astro`)

Сверху вниз: **`HeroStage`** (кадры, имя, бирка «Профессия · тэглайн», портрет-кружок) → **цена над кнопками** (`от N ₽` + строка ТОЛЬКО о цене; без цены — «Цена по запросу» без дубля) → **`HeroCta`** («Заказать» + «В избранное», зазор `--s-2`) → **`StoryText`** → ролики `ReelsRow` → отзывы → «Похожие».

**`StoryText.astro` — текст структурой исходника** (поле `story`; у старых карточек без story модуль собирает разделы из `bio/offers/packageIncludes/quote` — вид один на всех). Раздел (`StorySection`, `data/specialists.ts`):

| Поле | Как выглядит |
| --- | --- |
| `title` | h2 антиквой `--w-head-lg` |
| `lead` | без `title` — крупная фраза антиквой (она и есть заголовок); под `title` — лид `--fs-lead` |
| `text`, `after` | абзацы до/после списка |
| `list` / `tiles` | пилюли `.plates`, если все пункты ≤ 44 знаков, иначе `.list` |
| `items[]` | пункт с именем: имя — жирный Onest в кегле текста, текст вплотную (`--s-1`); `photo` — кружок слева (нет фото — инициалы у всех пунктов раздела) |
| `kind: 'menu'` | пункты меню одной плашкой `--surface`, состав `--fs-small` |
| `tariffs[]` | карточки тарифов: шапка «название — цена (+unit)», `lead`, `includes` списком, `note` прижат вниз. Всё, что о тарифе, — внутри карточки |
| `tone: 'dark'` | раздел на шоколаде + подпись «— Имя». У подрядчиков ПОКА НЕ СТАВИМ (заказчик, 08.10) |

Ритм: между разделами `--section-gap`; раздел без заголовка с крупной фразой — `--s-6`; продолжение обычным абзацем — абзацный `--s-4`. **Паузы фото:** после каждого второго раздела один вертикальный кадр из середины съёмки (`.shot`). Портрет автора (`portrait`) — над текстом, на ПК липкой колонкой.

## 4. Страница площадки (`ploshchadki/[slug].astro`)

Тело — список блоков `VenueBlock` из данных (порядок задаёт площадка): `stats`, `scenes`, `statement`, `story`, `terms`, `rules`, `docs`, `halls-index`, `halls`, `reels`, `reviews`, `faq`. Новый тип — новый компонент + ветка в странице + строка в скилле `venue-page`.

- **Бирок-надзаголовков над заголовками нет** («Условия», «Вопросы», «Где это»…): три заголовка подряд об одном и том же. Подзаголовок под именем площадки (`venue.kicker` «Усадьба · Барвиха») и тип зала в плитке оглавления — остаются.
- **Номеров у сцен и залов нет.**
- **Факты первого экрана** (`VenueHero`, вместимость/площадь/форматы) — на телефоне один столбец без линий, с 720px — две колонки.
- **Факты «да/нет» строками не выводим** («Кухня: своя», «Алкоголь: можно») — это техкарта; если важно — фразой в абзаце.
- **Сцены** (`ScrollyScenes`): на телефоне кадр `.shot` → заголовок антиквой 28–40 → текст; на ПК — липкий кадр колонкой в край экрана.
- **Залы** (`VenueHalls`, Гребнево): один кадр `.shot`, имя, три числа, тариф таблицей, «В аренду входит» + описание одной группой. Сверху — **липкая полоса пилюль залов** сплошной шапкой от верха экрана, текущий зал подсвечен (IntersectionObserver).
- **Блок `story`** — слова самой площадки её структурой (Fish Point «Fish'ки ресторана», Villa Barvikha «Маленькая Италия…»), у модуля свой верхний отступ (`block`).
- **FAQ:** вопрос антиквой 24–32, ответ вплотную (`--s-2`), между парами `--s-6`.
- **Контактов партнёра на странице нет** — только «Заказать» и «В избранное»; адрес и «Как добраться» остаются (это сведения о месте).
- **Отзывы — витрина:** последние 10 с оценкой ≥ 4 (`showcaseReviews`), агрегат с источника не пересчитываем.

## 5. Первый экран карточки (`HeroStage`)

- Окно постоянной пропорции `--stage-ratio` 4:5: имя и счётчик от карточки к карточке на одном месте. Портрет и квадрат — `cover`, горизонталь — целиком `contain` на бумагу (режим ставит скрипт по пропорции файла).
- Подпись на бумаге под кадром, не на фото. Имя — до двух строк; бирка — тип и один топоним.
- Листалка — своя строка под кадром: полоса-прогресс + счётчик; стрелки только при `hover: hover`.
- Ролик в кадре играет сам при листании; кнопка звука только на странице карточки.
- **Долг:** в HTML печатаются все кадры карточки; отдавать дежурный + кадр из якоря, остальные JSON-строкой — отдельным заходом.

## 6. Каталог и карточки

- **Карточка подрядчика / площадки / «Похожих» / «Избранного»:** имя первой строкой жирным Onest, под ним цена весом корпуса и стиль тем же цветом (приглушать нельзя), сердце на кадре.
- **Полоса разделов подрядчиков** (`CategoryNav`) — пилюли `.chip` с числом карточек.
- **Фильтры:** на телефоне любая настройка — нижняя шторка (`FilterSheet`), над сеткой полоса чипов (`FilterBar`); на ПК шторка — постоянная колонка слева. Применяется сразу, сортировка через CSS `order` (DOM для поисковика не двигается), счётчики считаются на сборке (`lib/filter-counts.ts`).
- **Карта** (`VenueMap`): на весь экран до нижней полосы (`--dock-h`), подменяет выдачу. Метка — капсула с одной ценой (`pinLabel` сокращает), выбранная — инверсия; кластеры; «уже смотрел» — `opacity`. Площадка без `contacts.geo` молча выпадает с карты — координата обязательна.

## 7. Главная

- Шапки нет: знак «Свадебные секреты» (встроенный svg, см. `AGENTS.md`) и кабинет. Разделы — в `BottomDock` (на ПК — рельс слева).
- **Входы в разделы** (`EntryRail`/`CoverTile`): плитки 3:4 одного размера, кадры живых подрядчиков только портретом (`avatar`), `demo` в кадры не идёт.
- **Доска** (`PhotoBoard` + `lib/gallery.ts`): жадная масонри (`pickColumn` в `lib/masonry.ts` — низкая плитка не ложится под низкую), пропорция кадра настоящая, без полос во всю ширину; бесконечная лента — 44 плитки сразу, хвост порциями по 12. Источники: площадки, живые подрядчики, ролики долей (`blendReels`); с карточки не больше 8 плиток, у «портфолио = сам человек» (`SELF_PORTFOLIO`) — 3. Ролик — всегда отдельная плитка; ушедший с экрана отпускает `src` (декодеры).

## 8. Моушн и жесты

- Появлений при прокрутке нет. Фото сами не едут. Только `--ease-out`/`--ease-inout`, `prefers-reduced-motion` уважается глобально.
- **Ленты с нативным скроллом не объявляют `touch-action`** — иначе палец на ленте не листает страницу вниз. Исключение — `PhotoRail` (`pan-y`).
- Ховер — только под `@media (hover: hover)`. Подчёркивания ссылок нет, кроме ссылок внутри текста статьи.
