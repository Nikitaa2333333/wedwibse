## 2. Реестр элементов (global.css — ищем здесь, потом создаём)

**Плашка в плашке запрещена** (Никита, 20.10.2026). Подложка (`--surface`, карточка) не кладётся внутрь другой подложки: одна плашка — и содержимое прямо в ней. Нужно отделить кусок внутри — отступом и кеглем, а не второй рамкой. Поле ввода и полоса прогресса — элементы управления, а не плашки, их цвет бумаги на плашке допустим.

- **`.pill`** — единственная кнопка-действие. **`.chip`** — плашка-выбор (фильтры, вкладки разделов; `.chip__count` — число в ней).
- **`.plates`** — короткие факты пилюлями россыпью (заливка `--surface`, без маркера). Только пункты в одну строку; длинные — `.list`. Каждая пилюля своей ширины, по тексту: до края ряда не растягиваем (24.10 — в неполном ряду короткие пункты раздувало пустотой). Растягиваются только кнопки действий парой (`HeroCta`, низ шторки фильтров), не плашки и не чипы.
- **`.list`** — единственный маркер списков (квадрат `--bullet-*`). Линий между пунктами нет нигде.
- **`.rows`** — строки «метка — значение». Один столбец по умолчанию; две колонки (`.rows--pairs`) ставит `rowsClass()` из `lib/rows.ts`, только если все пары короче 30 знаков. Линий нет; линии — только в таблице цен (`VenueTerms`, тариф зала).
- **`.shot`** — кадр внутри страницы карточки: 4:5, `--radius-card`, в полях страницы. Один вид у подрядчика (паузы между разделами, портрет) и площадки (сцены, залы). Слайдеров внутри страницы нет.
- **`.media` / `.media--bleed`** — кадр во всю ширину (первый экран). `PhotoRail` — единственный слайдер (первый экран, карточки каталога, доска).
- **`.sheet`** — нижняя шторка любой настройки (`lib/sheet.ts`); `--dock` на ПК — колонка слева.
- **`.theme-dark`** — инверсия секции (тон, не цвет).
- **`.hero-actions` / `.hero-btn`** — назад · избранное · поделиться поверх первого кадра; тонкий светлый ободок, чтобы не сливаться с тёмными секциями.
- **`.save`** — сердце на кадре (каталог площадок и подрядчиков), снимок общий с карточкой.
- **`<mark>`** — подложка `--mark` под тем же цветом текста. Используется в статьях; в карточках подрядчиков выделения нет (заказчик, 08.10).
- **`.veil` (затемнение фото) удалено** — текста на фото нет, затемнений нет нигде.

## 3. Страница подрядчика (`podryadchiki/[category]/[slug].astro`)

Сверху вниз: **`HeroStage`** (кадры, имя, бирка «Профессия · тэглайн», межстрочное `--lh-snug`, портрет-кружок) → **цена над кнопкой** (`от N ₽` + строка ТОЛЬКО о цене; без цены — «Цена по запросу» без дубля) → **`HeroCta`** (одна залитая «Заказать», во всю ширину на телефоне; «В избранное» словами снята 09.11 — избранное сердцем на кадре) → **`StoryText`** → ролики `ReelsRow` → отзывы → «Похожие».

**`StoryText.astro` — текст структурой исходника** (поле `story`; у старых карточек без story модуль собирает разделы из `bio/offers/packageIncludes/quote` — вид один на всех). Раздел (`StorySection`, `data/specialists.ts`):

| Поле | Как выглядит |
| --- | --- |
| `title` | h2 антиквой `--w-head-lg` |
| `lead` | без `title` — крупная фраза антиквой (она и есть заголовок); под `title` — лид `--fs-lead` |
| `text`, `after` | абзацы до/после списка |
| `list` / `tiles` | пилюли `.plates`, если все пункты ≤ 44 знаков, иначе `.list` |
| `items[]` | пункт с именем: имя — жирный Onest в кегле текста, текст вплотную (`--s-1`); `photo` — кружок слева (нет фото — инициалы у всех пунктов раздела) |
| `kind: 'menu'` | пункты меню одной плашкой `--surface`, состав `--fs-small` |
| `tariffs[]` | карточки тарифов: шапка «название — цена (+unit)», `lead`, `includes` списком, `note` прижат вниз. Всё, что о тарифе, — внутри карточки |
| `stats[]` | цифры-факты `{value, label}` («15+ лет», «700+ торжеств»): крупное число и подпись — та же сетка `StatsStrip` (`inline`), что полоса цифр площадки, две колонки |
| `tone: 'dark'` | раздел на шоколаде + подпись «— Имя». У подрядчиков ПОКА НЕ СТАВИМ (заказчик, 08.10) |

Ритм: между разделами `--section-gap`; раздел без заголовка с крупной фразой — `--s-6`; продолжение обычным абзацем — абзацный `--s-4`. **Паузы фото:** после каждого второго раздела один вертикальный кадр из середины съёмки (`.shot`). Портрет автора (`portrait`) — над текстом, на ПК липкой колонкой.

## 4. Страница площадки (`ploshchadki/[slug].astro`)

Тело — список блоков `VenueBlock` из данных (порядок задаёт площадка): `stats`, `scenes`, `statement`, `story`, `terms`, `rules`, `docs`, `halls-index`, `halls`, `reels`, `reviews`, `faq`. Новый тип — новый компонент + ветка в странице + строка в скилле `venue-page`.

- **Бирок-надзаголовков над заголовками нет** («Условия», «Вопросы», «Где это»…): три заголовка подряд об одном и том же. Подзаголовок под именем площадки (`venue.kicker` «Усадьба · Барвиха») и тип зала в плитке оглавления — остаются.
- **Номеров у сцен и залов нет.**
- **Факты первого экрана** (`VenueHero`, вместимость/площадь/форматы) — на телефоне один столбец без линий, с 720px — две колонки.
- **Факты «да/нет» строками не выводим** («Кухня: своя», «Алкоголь: можно») — это техкарта; если важно — фразой в абзаце.
- **Сцены** (`ScrollyScenes`): на телефоне кадр `.shot` → заголовок антиквой 28–40 → текст; на ПК — липкий кадр колонкой в край экрана.
- **Залы** (`VenueHalls`, Гребнево): один кадр `.shot`, имя, три числа, тариф таблицей, «В аренду входит» + описание одной группой. Сверху — **липкая полоса пилюль залов**, текущий зал подсвечен (IntersectionObserver). В потоке стоит сразу под плитками залов обычным шагом секции; поле под плавающие кнопки и бумага над полосой появляются, только когда она прилипла (`is-stuck`) — постоянный отступ давал дыру ~90 px между плитками и пилюлями (09.11).
- **Блок `story`** — слова самой площадки её структурой (Fish Point «Fish'ки ресторана», Villa Barvikha «Маленькая Италия…»), у модуля свой верхний отступ (`block`).
- **FAQ:** вопрос антиквой 24–32, ответ вплотную (`--s-2`), между парами `--s-6`.
- **Контактов партнёра на странице нет** — только «Забронировать» (одна залитая кнопка) и сердце на кадре; адрес и «Как добраться» остаются (это сведения о месте).
- **Отзывы — витрина:** последние 10 с оценкой ≥ 4 (`showcaseReviews`), агрегат с источника не пересчитываем.

## 5. Первый экран карточки (`HeroStage`)

- Окно постоянной пропорции `--stage-ratio` 4:5: имя и счётчик от карточки к карточке на одном месте. Портрет и квадрат — `cover`, горизонталь — целиком `contain` на бумагу (режим ставит скрипт по пропорции файла).
- Подпись на бумаге под кадром, не на фото. Имя — до двух строк; бирка — тип и один топоним.
- Листалка — своя строка под кадром: полоса-прогресс + счётчик; стрелки только при `hover: hover`.
- Ролик в кадре играет сам при листании; кнопка звука только на странице карточки.
- **Долг:** в HTML печатаются все кадры карточки; отдавать дежурный + кадр из якоря, остальные JSON-строкой — отдельным заходом.

## 6. Каталог и карточки

- **Карточка подрядчика / площадки / «Похожих» / «Избранного»:** имя первой строкой жирным Onest, под ним цена весом корпуса и стиль тем же цветом (приглушать нельзя), сердце на кадре.
- **Полоса разделов подрядчиков** (`CategoryNav`) — пилюли `.chip` с числом карточек. Под ней шапка раздела (`ScopePicker`) плотно: до заголовка `--s-3`, ряды чипов «локация» и «Фильтры · Популярные» одним шагом `--s-2` по обеим осям, как у Apple (09.11).
- **Фильтры:** на телефоне любая настройка — нижняя шторка (`FilterSheet`), над сеткой полоса чипов (`FilterBar`); на ПК шторка — постоянная колонка слева. Применяется сразу, сортировка через CSS `order` (DOM для поисковика не двигается), счётчики считаются на сборке (`lib/filter-counts.ts`).
- **Карта** (`VenueMap`): на весь экран до нижней полосы (`--dock-h`), подменяет выдачу. Метка — капсула с одной ценой (`pinLabel` сокращает), выбранная — инверсия; кластеры; «уже смотрел» — `opacity`. Площадка без `contacts.geo` молча выпадает с карты — координата обязательна.

## 7. Главная

- Шапки нет: знак «Свадебные секреты» (встроенный svg, см. `CLAUDE.md`), тумблер темы и кабинет. Тумблер и кабинет — **под** знаком по краям, прижаты к нему: строка кнопок заходит вверх на уровень подписи «WED SECRETS» (`margin-top: -var(--s-6)`), знак и кнопки — один блок (заказчик, 13.10.2026; вариант «над знаком» от 12.10 отменён). Разделы — в `BottomDock` (на ПК — рельс слева).
- **Входы в разделы** (`EntryRail`/`CoverTile`): плитки 3:4 одного размера, кадры живых подрядчиков только портретом (`avatar`), `demo` в кадры не идёт.
- **Доска** (`PhotoBoard` + `lib/gallery.ts`): жадная масонри (`pickColumn` в `lib/masonry.ts` — низкая плитка не ложится под низкую), пропорция кадра настоящая, без полос во всю ширину; бесконечная лента — 44 плитки сразу, хвост порциями по 12. Источники: площадки, живые подрядчики, ролики долей (`blendReels`); с карточки не больше 8 плиток, у «портфолио = сам человек» (`SELF_PORTFOLIO`) — 3. Ролик — всегда отдельная плитка; ушедший с экрана отпускает `src` (декодеры).

## 8. Моушн и жесты

- Появлений при прокрутке нет. Фото сами не едут. Только `--ease-out`/`--ease-inout`, `prefers-reduced-motion` уважается глобально.
- **Ленты с нативным скроллом не объявляют `touch-action`** — иначе палец на ленте не листает страницу вниз. Исключение — `PhotoRail` (`pan-y`).
- Ховер — только под `@media (hover: hover)`. Подчёркивания ссылок нет, кроме ссылок внутри текста статьи.

## 11. Фото: пропорции — система на весь каталог

> Перенесено из `CLAUDE.md` 05.11.2026 без правок текста. Оптимизация файлов (`<Image>`, `IMG_WIDTHS`, `sizes`) — `docs/IMAGES.md`.

Каталог вырастет до тысяч фото, отсматривать каждое при вёрстке не будем —
значит показ фотографии не должен зависеть от того, кто именно её проверил
на глаз. Два правила держат это без ручной проверки:

- **Доска на главной** (`PhotoBoard` / `lib/gallery`) показывает кадр
  в его настоящей пропорции — реф. Pinterest, плитки разной высоты.
- **Первый экран карточки** (`HeroStage`, и площадка, и подрядчик) —
  наоборот, окно ПОСТОЯННОЙ пропорции `--stage-ratio` (4:5). Кадр
  в своей высоте означал, что от карточки к карточке разъезжается всё:
  имя, бирка, счётчик кадров каждый раз на новой высоте, и человек,
  листающий каталог, ищет их заново. В каталоге на тысячи карточек
  предсказуемость важнее точности кадра.
  **Но запрет «не кроить в общее окно» внутри этого окна живой** — он
  и родился из того, что горизонтальный студийный кадр однажды срезало
  по сюжету пополам. Поэтому: портрет и квадрат заполняют окно (`cover`),
  а горизонтальный кадр вписывается в него ЦЕЛИКОМ (`contain`) на бумагу,
  высота окна при этом не меняется. Режим ставит скрипт по настоящей
  пропорции файла — из CSS её не спросишь.
- **Вертикальность — одна граница на весь проект**, `isPortrait()` /
  `PORTRAIT_MAX_RATIO` в `lib/media.ts`. Раньше то же число жило только
  внутри доски, а первый экран площадки при выборе дежурного кадра считал
  вертикальность на свой лад — с ростом каталога такие развилки в двух
  местах не отсматриваются, они тихо накапливаются. Кому нужно «это
  вертикальный кадр?» — импортирует функцию, второго числа не заводит.
- **Мобилка — главный сценарий, значит горизонтальным в галерее площадки
  в целом не место.** Правило на будущее при заведении фото новых
  площадок/подрядчиков: галерея курируется вертикальными и квадратными
  кадрами по умолчанию, горизонтальный — исключение (широкий панорамный
  кадр внешнего вида и т.п.), не норма. Тогда любой кадр, по которому
  нажали в доске или в галерее, открывается вертикально и во весь экран
  телефона сам по себе — не нужно её отдельно подбирать под первый экран.
- **Портрет автора — своё поле `avatar`, а не кадр из галереи.** Кадры
  карточки это разные вещи в разных категориях: у ведущего в `photos` он
  сам, а у фотографа, видеографа, декоратора — его РАБОТЫ, и человека,
  с которым предстоит иметь дело, не видно нигде. Вырезать лицо из
  портфолио нельзя: свадебный кадр ростовой, квадратный кроп даёт грудь.
  Портрет присылает подрядчик отдельным файлом, кладём в
  `src/assets/specialists/<категория>/avatars/<slug>.webp` (квадрат,
  лицо в центре, от 400 px). Рисует всегда компонент `Avatar` — своих
  кружков по страницам не заводим: нет портрета, он сам ставит инициалы.
  На визитке кружок стоит всегда (слот держит вёрстку), в сетке каталога
  — только с реальным фото: кружок с буквами на каждой карточке шум.
- **Десктоп этим заходом не занимались** — первый экран площадки на ПК
  сейчас просто ограничен по высоте (`max-height`, `object-fit: contain`),
  чтобы вертикальный кадр не превращался в отвесную полосу на два экрана.
  Постоянное решение под широкий экран (например, коллаж из двух кадров
  рядом) — отдельная задача, не сейчас.

## 12. Навигация: сценарий мобилки и десктопа — не один UI

> Перенесено из `CLAUDE.md` 05.11.2026 без правок текста. Это правила **сайта**. В кабинете «назад» — `<BackButton plain>`, см. `.claude/skills/cabinet-ui/SKILL.md`.

Mobile-first задаёт вёрстку, но не значит «одна и та же навигация везде,
только сжатая». У мобилки и десктопа разные способы вернуться назад —
жест/системная кнопка на телефоне, мышь и клавиатура на ПК — и решение
должно быть разным по существу, не одной уменьшенной копией.

- **Карточка-«потомок» (провалились из каталога вглубь: площадка,
  специалист, статья блога) — навигация «назад», не хлебная крошка
  текстом.** Крошка текстом — паттерн сайта с постоянной шапкой; у нас
  шапка скрыта (см. `SiteHeader.astro`, `display: none` на время
  дизайн-фазы), а сама строка «Главная / Площадки / …» поверх фото или
  над ним съедала экран и на телефоне читалась как мусор перед главным —
  самой площадкой.
- **Компонент `BackButton.astro`** — ЕДИНСТВЕННАЯ кнопка «назад» проекта:
  чернильный квадрат со скруглением карточки (`.hero-btn`). Своих стрелок
  по страницам не рисуем (25.09.2026 в полосе вкладок каталога нарисовали
  серый кружок `.icon-btn` вместо неё — заказчик поймал сразу). Стоит
  в ряду действий карточки (`HeroActions`) и в полосе вкладок каталога
  специалистов (`CategoryNav`, там `history={false}` — всегда на хаб).
  Раздел из нижнего дока («Площадки», «Специалисты», «Избранное») — это
  не потомок, ему кнопка «назад» не нужна, он сам корень своей ветки.
  Ссылка настоящая (`href` на раздел-родитель) — переход по ней остаётся
  в HTML и работает без JS; клиентский скрипт поверх подменяет его на
  `history.back()`, если у вкладки есть история этого же сайта (обычный
  путь — пришли из каталога), и оставляет обычный переход по ссылке,
  если попали прямым заходом (поиск, закладка — истории нет).
- **Внутренняя перелинковка на раздел не потеряна** — она живёт в самом
  `href` кнопки «назад», просто без видимого текста «Площадки» рядом.
  Микроразметка `BreadcrumbList` (задача в `docs/seo/SEO.md`, п. про заготовки)
  не завязана на видимую крошку — это отдельный `<script type="application/ld+json">`
  в `<head>`, ставится независимо и решает то же для поисковика.
- **Главная полоса разделов — одна на обе платформы, но не одна и та же
  форма** (`BottomDock.astro`, тот же принцип, что выше): на телефоне это
  фиксированный таб-бар снизу с подписями под иконками, на ПК (от 1024px)
  — вертикальный рельс слева шириной `--rail-w`, одни иконки без подписей
  (реф. Pinterest). Не «сжатый таб-бар»: на широком экране полоса снизу
  тратит целую строку ради четырёх ссылок и уводит руку от мыши.
  Место под полосу держит один слой — `body { padding-left: var(--rail-w) }`
  в `global.css`; страницы читают только `--dock-space` (снизу на телефоне,
  обычный отступ секции на ПК) и не знают, где полоса стоит сейчас.
  Фиксированные элементы (плавающая панель сравнения в «Избранном»)
  считаются от вьюпорта, а не от контента — им `--rail-w` вычитается руками.
- **Не сделано (следующий шаг, не сейчас):** старый блог удалён 05.11.2026,
  новый пишется заново — сразу с кнопкой «назад». Верхней шапки на ПК тоже
  пока нет — `SiteHeader` выключен целиком до конца дизайн-фазы, и когда
  его будут включать, разводить мобилку/десктоп заново по этому же
  принципу, а не чинить одним общим компонентом.
