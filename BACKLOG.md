## Задача: боевая инфраструктура — VPS + бакет + git (25.09)

Цель: git хранит только код и данные карточек, файлы — в бакете,
VPS отдаёт сайт и держит живую базу. Сейчас бакета нет вовсе.

Что где сейчас и чем грозит:

- **PocketBase — только на ноутбуке** (`pb/pb_data`). На сервере базы нет;
  сломается ноутбук — база каталога пропала. **Делать первым.**
- **Фото карточек в git** (`src/assets`, ~430 МБ) — растёт с каждым
  подрядчиком, при тысячах кадров репозиторий станет неподъёмным.
- **Ролики — только папка на VPS** (`/var/www/wedsecrets-media`, ~110 МБ)
  и локальный `public/`. Резервной копии нет.
- **Сырьё с дисков подрядчиков** (`research/`) — только на ноутбуке.

План, по шагам:

1. **PocketBase на VPS**: бинарник + systemd-сервис, `pb_data` на сервере,
   миграции из `pb/pb_migrations`, nginx-прокси на поддомен или путь
   (админка для модератора), перенос текущих данных с ноутбука.
   Скрипты `pb-seed-*` / `pb-pull` — переключить `PB_URL` на боевой адрес.
2. **Бакет Timeweb S3** (приватный, Москва). Нужно от заказчика: создать
   в панели и положить в `.env` `S3_ACCESS_KEY`, `S3_SECRET_KEY`, имя
   бакета — либо дать API-токен Timeweb, создадим через CLI.
3. **Бэкапы в бакет**: ночной снимок `pb_data` с VPS (cron), сырьё `research/`.
4. **Ролики**: главная копия — бакет; `media-push.sh` льёт в бакет, VPS
   тянет оттуда в `/var/www/wedsecrets-media` (адреса роликов не меняются).
5. **Фото из git в бакет**: деплой перед `astro build` делает
   `s3 sync бакет → src/assets`, дальше пайплайн `astro:assets` как был
   (правило «фото только через `<Image>`» не меняется). Файлы уходят из git
   в `.gitignore`, секреты S3 — в GitHub Secrets. Старые кадры в истории
   git — отдельным решением (force-push).
6. Обновить AGENTS.md (хостинг), скиллы `specialist-page` / `venue-page`
   (куда класть фото и ролики), VIDEO.md.
