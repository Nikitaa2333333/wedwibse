# Пункт управления — карта проекта

Карта — главный рабочий инструмент владельца (Никита, 05.11.2026): все статусы,
успешные пути, недоделки и проблемы в одном месте, и лента сессий — кто, где,
что сделал. Новый чат не видит прошлых разговоров: что не записано в карту,
того для владельца не было.

- Вид: `docs/map/index.html` (открывается файлом в браузере). Данные: `docs/map/data.js`.
- **Данные руками не править** — только `node scripts/map.mjs …` (он проверяет целостность;
  один лишний символ в 5000 строк — и карта пустая).
- Короткий план одним экраном — `ROADMAP.md`; он и карта меняются в одном коммите.

## Когда обновлять

1. **Закрыл или сдвинул шаг** — сразу, в том же коммите, что и код:
   `node scripts/map.mjs step <дорожка> "<часть текста шага>" done "что сделано, коммит"`.
   Нет такого шага — `add-step`. Найти шаг: `node scripts/map.mjs find "<текст>"`.
2. **Нашёл проблему** — `add-issue "<название>" high|mid|low "<область>" "<как чиним>" "<файл:строка>"`;
   починил — `issue "<часть названия>" done "что сделано"`.
3. **Решение владельца** («оставляем», «отложим», «делаем так») — `decision "<тема>" "<решение>"`.
4. **Конец сессии** (или пауза, длинный разговор, ждём внешнее) — итог в ленту:
   файл JSON в scratchpad → `node scripts/map.mjs session итог.json`:
   ```json
   { "title": "Коротко, о чём сессия", "where": "локально | облако",
     "summary": "2–3 фразы человеческим языком",
     "done": ["что сделано — по пунктам"], "decided": ["решения владельца"],
     "next": ["что дальше"], "tracks": ["clean", "cabinet"],
     "branch": "claude/…", "commits": ["abc1234"] }
   ```
   Повторный вызов с тем же названием и датой обновляет запись, а не плодит новую.
5. `node scripts/map.mjs check` — перед коммитом карты.

Дорожки (`tracks`): vitrina, content, seo, cabinet, venuecab, auth, moder, pilot, leads,
bride, mail, ssr, server, legal, promo, clean, money. Список — `node scripts/map.mjs check`
и поле `id` в `data.js`.

## Облачная сессия

То же самое: скрипт и данные лежат в git. Итог — коммитом в свою ветку; в master
карта попадает вместе с работой. Конфликт в `data.js` при слиянии: взять обе
стороны и прогнать `node scripts/map.mjs check` — порядок записей не важен,
важна целостность.

## Правила записи

- Человеческим языком, без жаргона: карту читает владелец, а не разработчик.
- Статус — правда: `done` только когда выложено или проверено; в ветке — `work`
  с заметкой «в ветке …, не выложено».
- Не выдумывать цифры и даты; источник — коммит, файл, слова владельца.
- Сообщения людям, деньги, удаления — не «сделано» без явного «да» владельца.
