# WED Secrets — законы проекта

Свадебный агрегатор площадок и подрядчиков Москвы и МО (wed-secrets.ru). Не путать с wedwed.ru:
это конкурент, разбор в `docs/seo/SEO.md`. Два контура: витрина для невесты (сайт, SEO-каталог)
и кабинет подрядчика/админка (`/profi/`, второй этап). Идёт второй этап: кабинет, модерация, пилот.

- План и статус — `ROADMAP.md` и **пункт управления** `docs/map/index.html` — главный инструмент владельца.
  Каждая сессия, локальная и облачная, пишет туда статусы и итог: скилл `control-map`,
  только через `node scripts/map.mjs` (данные `docs/map/data.js` руками не править). Решения — `docs/DECISIONS.md`.
  Правили файлы, а карту не тронули — хук Stop (`scripts/map-hook.mjs`) не даст закончить ответ.
- Хвосты и недоделки — `BACKLOG.md`: заметил и оставил на потом — строка туда сразу, сделал — строку удалить.
- Это файл законов, нужных в каждом чате. Справочники, истории поломок и процедуры — в `docs/` (указатель внизу).
- Дизайн сайта — скилл `site-design`; кабинет и админка — скилл `cabinet-ui`. Читать нужный до правки интерфейса.

## Масштаб продукта: что запрещено с первой строки кода

Это не лендинг, а каталог с фильтрами, посадочными страницами как главным SEO-инструментом, кабинетом и CRM.

- Скорость. Никаких тяжёлых библиотек и клиентских фреймворков ради красоты. Моушн — CSS и Lenis
  (в `package.json` только `lenis`; GSAP не установлен). Каждая новая клиентская зависимость — с обоснованием.
- SEO. Контент статикой или с сервера в HTML, не рисуется клиентским JS. Семантическая разметка сразу.
- Каталог. Секции — переиспользуемые модули (карточка площадки, полоса фильтров, блок «текст + список»),
  ничего намертво привязанного к одной странице.
- Фиксированный SEO-фундамент: серверная сборка, URL `/moskva/ploshchadki/nazvanie/`, автозаголовки
  из данных карточки, открытая пагинация.
- Числа («25 карточек», «6 площадок») в законы не пишем: они устаревают, живут в ROADMAP.

## Изображения (подробности и история — `docs/IMAGES.md`)

**Принцип (Никита, 06.11.2026): фото готовится один раз — когда попадает к нам,
а не когда его смотрят. Программа страниц фото не режет.** Нарезку делает отдельный
сервис фото, запускается она по «Готово» подрядчика; один раз нарезанное второй раз
не режем. План — `docs/PHOTO-SERVICE.md`.

- Фото карточек, галерей и героев — только `<Image>` / `<Picture>` из `astro:assets`, не сырой `<img>`.
- Источник — `src/assets/...`, не `public/`. Путь в данных — строкой, на выводе через `resolveImage()` (`src/lib/images.ts`).
- `widths` — только роль из `IMG_WIDTHS` (hero, wide, card, tile, stage, thumb), не массив от руки.
  `sizes` — реальная доля экрана на каждом брейкпоинте. Новая роль — в реестр, не литерал.
- В `src/assets` кладём материал, а не результат: не пережимать перед укладкой. Длинная сторона 2400–3000 px, webp q88.
- Новую пачку кадров прогнать `magick identify` до постановки в данные (битый webp доезжает до сайта молча).
- `public/` — только то, что обязано быть стабильным сырым URL: og-картинка, favicon.
- Постер ролика — обычное фото 1080×1620 из оригинала.

## Пропорции фото (подробно — `DESIGN.md`, разделы 5 и 11)

- Доска на главной показывает кадр в настоящей пропорции; первый экран карточки — окно `--stage-ratio` (4:5):
  портрет и квадрат `cover`, горизонтальный `contain` целиком.
- Вертикальность — одна граница на проект: `isPortrait()` в `lib/media.ts`, второго числа не заводим.
- Галерея курируется вертикальными и квадратными кадрами; портрет автора — отдельное поле `avatar`, рисует `Avatar`.

## Карточки

- Страница площадки — список блоков `VenueBlock`; заводится только скиллом `venue-page`. Подрядчик — скиллом
  `specialist-page`, обязательно с записью в PocketBase (карточка без записи не заведена).
- Текст карточки — структурой исходника (поле `story`), своих разделов не досочиняем; сверка
  `node scripts/text-coverage.mjs` не ниже 95 % (`docs/CHARACTER.md`).
- Фильтры подрядчиков — только в `src/data/specialist-filters.ts`; столбец в таблицу модератора руками не заводим (`docs/REGISTRY.md`).

## Подрядчик пишет только в `revisions`

- В `venues` / `specialists` подрядчик не пишет никогда — ни правилом `owner = auth`, ни «с проверкой статуса».
  Карточку создаёт и меняет одобрение модератора (хук `pb/pb_hooks`). Закрыто отсутствием доступа, а не проверкой.
- Новое поле в шаблоне кабинета — в белый список `pb/pb_hooks/lib/cabinet.js`, служебное поле туда не добавлять.
- Тронул хуки, правила коллекций или миграцию кабинета — `node scripts/pb-test-cabinet.mjs` против базы с `--hooksDir`.
- Хуки на сервер — только с только что подтянутого master: `git fetch`, перебазироваться, тесты, заливка, сверка md5 (`docs/DEPLOY.md`).
- Карточки из кабинета (`page.source = "cabinet"`) рисует сервер из базы, в `src/` их не выгружаем.

## Кабинет и админка — не сайт

Правила дизайн-системы сайта (бумага/чернила, антиква, `.pill` на всё) в кабинете не действуют. Цвет несёт смысл
(`--st-*`), статус плашкой, действие текстом, плотно, без выдуманных цифр. Исключение — экраны входа, регистрации,
пароля, приглашения и промо: они в стиле сайта по решению владельца (31.10). Всё — в скилле `cabinet-ui`.

## Видео (`docs/VIDEO.md`)

- Astro видео не пережимает: ролик готовится заранее по `docs/VIDEO.md` (до 60 с, H.264, 720p, до 8 МБ, постер `.webp`).
- Ролики не в git, а на VPS: `bash scripts/media-push.sh` ДО пуша кода, который на них ссылается.
- Добавили ролики — `node scripts/verify-video.mjs`.
- Звука в выдаче нет (кнопка только на странице карточки). Ролик без автора (`author` или `venue`) в ленту не ставим.

## Ловушки (разбор — `docs/TRAPS.md`)

- У вертикального скролл-бокса ось X закрываем явно: `overflow-x: clip`. Полю ввода в grid — `min-width: 0` у ячейки.
- Всплывающие поверхности — только через `bindSheet` / `.sheet` (`lib/sheet.ts`): блокировка фона на айфоне уже внутри.
- Внутренности чужого компонента через `:global()` снаружи не переопределяем, если от этого зависит размер или пропорция:
  вместо этого проп на самом компоненте.
- Процентная высота внутри flex-элемента — `flex: 1 1 0`, не `1 1 auto`.

## Дизайн сайта: короткие законы (полно — скилл `site-design`, `DESIGN.md`)

- Все значения — токены `src/styles/global.css`; хардкод цветов, отступов, радиусов, длительностей запрещён. Нужна ручка — новый токен.
- Сначала реестр (`DESIGN.md` §2), потом новое. Новый элемент сразу в `global.css`, не в стилях страницы.
- Текст не лежит на фото, затемнений нет. На кадре только сердце `.save` и кнопки `.hero-btn`.
- Onest — набор и служебное; Cormorant — только крупные заголовки и фразы. Вес — четыре токена `--w-*`.
- Бумага/чернила, цветных заливок нет. Плашка в плашке запрещена. Без бирок-надзаголовков, номеров и линий между пунктами.
- Капс запрещён (кроме аббревиатур и марок). Жирность внутри фразы запрещена: выделение только `<mark>`. Текст контрастный, без opacity и серого для приглушения. Мера строки в `ch` на самом текстовом элементе (токены `--measure-*`).
- Скругления по роли: `--radius-card` в полях страницы, `--radius-media` (0) у кадра во всю ширину.
- Межстрочное: мелкий пункт в 2–3 слова — `--lh-caption`; фраза в несколько строк — `--lh-body`.
- Логотип — встроенный `<svg>` из `public/logo-tag.svg`, красится `currentColor`; новый знак — новое имя файла.

## Mobile-first

- Базовая вёрстка под телефон (375–430 px), десктоп — расширение, только `min-width`.
- Моушн на мобилке: transform и opacity, без blur/filter-анимаций, тяжёлых канвасов и параллакса.
- «Вау» — только в `@media (min-width: 1024px) and (pointer: fine)`; ховер — только под `@media (hover: hover)`.
- Lenis не трогает нативный тач-скролл.

## Навигация (подробно — `DESIGN.md` §12)

- Карточка-потомок получает `BackButton`, а не крошку текстом; другой кнопки «назад» на сайте нет.
- Разделы: на телефоне таб-бар снизу (`BottomDock`), на ПК от 1024 px рельс слева. Верхняя шапка `SiteHeader` выключена (`display: none`).

## Моушн

- Появлений блоков при прокрутке нет и не заводим без отдельной просьбы. Только `--ease-out` / `--ease-inout`; linear не использовать.
- `--dur-*` и `--ease-*` — для ховеров, шторок и перекладок, то есть для реакции на действие.

## Рабочий режим

- Быстрые целенаправленные итерации: просят поправить элемент — делаем сразу, без разведки.
- Каждая находка — во внутренний документ, не остаётся в чате (SEO — `docs/seo/`, отступы — `SPACING.md`, дизайн — `DESIGN.md`).
- Данные отдельно от вёрстки, компоненты переиспользуемые, заглушки помечаем комментарием.
- Скриншоты: пользователю пачки не показываем и Playwright для просмотра не гоняем, но для себя после правок вёрстки
  разрешён `node scripts/shot.mjs <путь> <селектор> research/shots/x.png` на ширине телефона (390 px), до того как отдавать.
- Полную `astro build` ради мелкой правки не запускать (5–7 минут без кэша). Нужно глазами — `astro dev`. Полная сборка —
  когда менялись данные карточек или конфиг, и в Actions с кэшем.
- Вьюпорт пользователя ~1280 CSS px — в глобальных правилах.

## Деплой (подробно — `docs/DEPLOY.md`)

- Сайт обновляется только пушем в master: `.github/workflows/deploy.yml` собирает и заливает `rsync --checksum` (около минуты). Руками на сервер ничего не копировать.
- Сервер: VPS Timeweb `193.124.47.78`, каталог `/var/www/wedsecrets`, вход `ssh -i ~/.ssh/timeweb_wed root@193.124.47.78`; сборка на сервере не идёт.
- Из `deploy.yml` не убирать `--checksum`, `--timeout=60`, лимиты `timeout-minutes` и шаг «Check SSH to server».
- Сайт открыт для поисковиков (`SITE_INDEXABLE: 'true'`): любая служебная, черновая или кабинетная страница обязана ставить `<meta name="robots" content="noindex">`.
- Пароли и токены в чат и в код не попадают; root-пароль в `.env` (в `.gitignore`).

## Development

- Дев-сервер: `astro dev --host 127.0.0.1 --port <свой>`; управление `astro dev stop / status / logs`.
- После серии правок стилей компонента перезапустить дев-сервер (иначе отдаёт старый CSS).
- Гасить свой сервер по PID, как только посмотрели.
