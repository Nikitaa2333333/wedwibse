# Сервис фото — задача (06.11.2026)

## Зачем

Принцип из `CLAUDE.md`: **фото готовится один раз — когда попадает к нам, а не когда
его смотрят. Программа страниц фото не режет.**

С 05.11 страницы каталога рисует служба `wedsecrets-ssr` (сайт из базы), и она же режет
фото под размеры экрана (`/_image`, sharp) при первом просмотре. Итог 05–06.11: 43 падения
службы по памяти за сутки, у заказчика — битые кадры и растянутое фото, первый посетитель
ждёт нарезки. 06.11 на сервере поставлена настройка памяти (`docs/DEPLOY.md`, «Память
службы») — падения ушли, но устройство осталось неправильным: страницы и нарезка в одной
программе, нарезка — в момент просмотра, фото из сборки режутся второй раз.

## Решения Никиты (06.11)

1. **Отдельный инструмент для фото.** Кандидат — imgproxy (открытый, libvips, ровная
   память, отдельный процесс: его сбой не роняет страницы). Перед выбором — официальная
   документация; сверить память на 2 ГБ сервера, формат адресов (подпись), webp/avif,
   кэш nginx перед ним (как `wedimg`, 30 дней).
2. **Резать по «Готово».** Подрядчик нажал «Готово» (ревизия ушла на модерацию) —
   нарезка всех размеров его кадров начинается сразу. Модерация дольше нарезки
   (карточка 50 фото × ~5 ширин ≈ 250 вариантов, по одному — порядка 2–3 минут),
   поэтому к одобрению всё готово. Вернули или удалили — ничего страшного: лишние
   варианты выпадут из кэша сами (`inactive=30d`). Одобрили раньше, чем нарезалось, —
   карточка ждёт готовности фото (минуты), а не выходит с пустыми кадрами.
   То же — для карточек конвейера (`pb-seed*` с `--publish`).
3. **Второй раз не резать.** Фото из `src/assets`, уже нарезанные при сборке
   (`/_astro/*`), страницы с сервера должны отдавать готовыми файлами, а не через
   повторную нарезку. Сейчас: на SSR-страницах даже такие кадры идут через `/_image`.

## С чего начать

- `src/lib/images.ts` (реестр, `IMG_WIDTHS` — набор ширин по роли: ими и резать),
  `src/lib/live-data.ts` (кадры из базы), `astro.config.mjs` (`image`),
  компоненты с `<Image>` на SSR-страницах.
- Хук «Готово» — `pb/pb_hooks/lib/cabinet.js` (отправка ревизии); заливка хуков —
  только по правилу `docs/DEPLOY.md` (свежий master → `pb-test-cabinet` → scp → md5).
- Сервер: nginx `/etc/nginx/sites-available/wedsecrets` (`location ^~ /_image`),
  кэш `/etc/nginx/conf.d/wed-cache.conf`; любые правки сервера — с копией, план
  Никите до правки.
- После перехода: убрать `scripts/warm-images.sh` и шаг прогрева в `deploy.yml`,
  строку «Память службы» в `docs/DEPLOY.md` переписать по факту.

## Готово, когда

- Служба страниц не вызывает sharp ни на одном запросе (проверка: журнал службы,
  память ровная при открытии тяжёлых страниц с холодным кэшем).
- Новая карточка: «Готово» → через ~3 минуты все варианты фото в кэше, первый
  посетитель после одобрения не ждёт ни одного кадра.
- Карта (`node scripts/map.mjs`) и `ROADMAP.md` обновлены в том же коммите.
