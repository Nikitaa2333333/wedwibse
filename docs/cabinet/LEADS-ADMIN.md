# Заявки пар в админке — задание (07.11.2026)

**Зачем.** Заявки пар (форма на карточке и «Написать всем» из избранного) сейчас
видны только в чате MAX «Уведомления Wed Secrets» и на почте `kabinet@`. В админке
их нет вовсе. Никита: «важно отслеживать, что приходит, и делать срез»; внутри
приложения нужна статистика — сколько заявок отправлено.

**Для кого.** Модератор и владелец (Никита, Евгений) в админке `/profi/admin/`.
Подрядчику заявки пока НЕ передаём (третий этап, «Деньги»): этот экран — только для нас.

**Правила, которые не нарушать.**
- Скилл `cabinet-ui` (кабинет — не сайт): плотно, цвет несёт смысл (`--st-*`),
  статус плашкой `.status`, действие текстом, тонкие стрелки `Glyph`.
- Никаких выдуманных цифр: только то, что лежит в `leads`. Нет данных — «нет данных», не ноль-заглушка.
- Телефон и имя пары — персональные данные: экран только под входом модератора,
  страница с `noindex`, в адресах и логах их нет.
- Сообщений людям экран не шлёт (кнопки «позвонить / написать» — обычные ссылки `tel:` / мессенджер).

## Что уже есть

- Коллекция `leads` (миграции `1757700000_init_catalog`, `1760900000_cabinet_stage2`,
  `1762200000_leads_route`): `kind`, `name`, `phone`, `email`, `message`, `venue`,
  `specialist` (связи — пока НЕ заполняются), `eventDate`, `guests`, `sourceUrl`,
  `consent`, `status` (`new` / `in-progress` / `done` / `spam`), `bride`, `created`.
- Модераторы читают и меняют заявки (`listRule`/`viewRule`/`updateRule` — модератор).
- Пишет их только хук `createLead` (`pb/pb_hooks/lib/cabinet.js`, маршрут `POST /api/wed/lead`):
  - с карточки — одна запись, `message` начинается с «Карточка: <имя>», `sourceUrl` — адрес карточки;
  - «Написать всем» (поле `cards` в запросе) — по записи на карточку в одной транзакции,
    в `message` строка «Из избранного, всем сразу (N)», `sourceUrl` — адрес каждой карточки.
- Меню админки — `src/components/admin/AdminShell.astro`; загрузчик данных — `src/lib/admin-live.ts`.
  Нынешний раздел «Заявки» (`/profi/admin/zayavki/`) — это НОВЫЕ КАРТОЧКИ подрядчиков, не заявки пар.

## Что сделать

1. **База (миграция + хук).** Чтобы срез не держался на разборе текста:
   - поле `source` (select: `card` / `favorites`) — откуда пришла заявка;
   - `createLead` заполняет `specialist` или `venue` по `sourceUrl`
     (`/moskva/podryadchiki/<кат>/<slug>/`, `/moskva/ploshchadki/<slug>/`) и `source`;
   - старые записи — разовым скриптом по тем же правилам.
2. **Меню.** «Заявки» → «Новые карточки» (адрес можно оставить); новый пункт
   «Заявки пар» → `/profi/admin/zayavki-par/` со счётчиком новых (`status = new`).
3. **Список.** Новые сверху: дата и время, имя, телефон (ссылка `tel:`), карточка
   (ссылкой на визитку), откуда (с карточки / из избранного — одна отправка группой
   видна как одна строка с перечнем карточек), дата свадьбы, сообщение, статус.
   Статус меняется в строке: новая → в работе → закрыта, отдельно «спам».
   Фильтры: статус, период, категория.
4. **Срез (статистика в приложении).** Плитками, как «Сводка» админки:
   заявок за сегодня / неделю / месяц; по категориям; топ карточек по заявкам;
   доля «из избранного»; сколько ещё в статусе «новая». Все цифры — запросом к `leads`.
5. **Сводка админки** — плитка «Заявки пар: N новых» со ссылкой в раздел.
6. **Тест.** `scripts/pb-test-cabinet.mjs`: заявка с карточки и группой получают
   `source` и связь с карточкой; подрядчик и гость заявки не читают; модератор меняет статус.

**Не делаем сейчас:** передачу заявки подрядчику, «Показать контакты» и журнал открытий
(отдельный шаг ROADMAP), просмотры карточек (они в Яндекс Метрике — отдельное решение,
тянуть ли их в админку).

**Выкладка:** хуки и миграция на сервер — по `docs/DEPLOY.md` (свежий master,
`pb-test-cabinet --hooksDir`, сверка md5). Сначала показать локально, в master — после «выкладывай».
