# Статистика: кабинет подрядчика и админка — задание (10.11.2026)

**Зачем (Евгений, 09.11).** Понимать результативность платформы и её востребованность у партнёров;
проще анализировать и работать с подрядчиками. «Что-то простое и понятное, по типу мобильной версии
Яндекс Директа»: строка — подпись, крупное число, справа график-заливка за период.

**Что показываем, с привязкой к дате:**
1. Переходы на страницу карточки.
2. Добавления в избранное.
3. Полученные заявки.
4. Расходы — появятся с балансом (третий этап). До того строки нет, а не «0 ₽».

**Кому.**
- Подрядчику — в кабинете, только по своим карточкам.
- Админке — общая с разбивкой по категориям (Площадки, Ведущие, Вокалисты, Кондитеры…)
  и персональная на экране каждого партнёра. По заявкам — число и график поступления: спрос на подрядчиков.

## Что уже есть

- Заявки: коллекция `leads` со связью `specialist` / `venue` и `created` (`docs/cabinet/LEADS-ADMIN.md`).
  Число и график по дням можно рисовать сразу, без новых данных.
- Переходов и избранного в базе нет. Просмотры есть только в Яндекс Метрике, избранное живёт в `localStorage`
  посетителя (`src/lib/favorites.ts`). Метрику по API в кабинет тянуть дорого (ключ, лимиты, страницы из базы
  без цели по карточке), поэтому считаем сами.

## Как сделать (предложение, не согласовано)

1. **Счётчик.** Маршрут `POST /api/wed/hit` в хуке: `{ card, kind: 'view' | 'fav' }` уходит через
   `navigator.sendBeacon` со страницы карточки (просмотр) и с сердца `.save` (избранное, только «добавил»).
   Хук прибавляет единицу в коллекции `card_stats` — одна строка на «карточка × день»: `card`, `day`,
   `views`, `favs`. Сырые хиты не храним: персональных данных нет, база не пухнет.
   Боты и повторы: не считаем без `Sec-Fetch-Site` своего сайта и с ботовым User-Agent; повтор той же
   карточки в одной вкладке — один просмотр (`sessionStorage`).
2. **Чтение.** Подрядчик читает только строки своих карточек (правило коллекции по `owner` карточки),
   модератор — все. Писать в `card_stats` может только хук.
3. **Экран.** Строки как у Директа: подпись, число за период, график-заливка по дням; период сегментами
   «7 дней / 30 дней / 90 дней». График — свой inline SVG без библиотек (закон скорости). Нет данных за день —
   пусто, не ноль; до запуска счётчика — «считаем с <дата>».
4. **Админка.** Раздел «Статистика»: те же строки за всё вместе, ниже таблица по категориям
   (переходы, избранное, заявки), нажатие — партнёры категории; на экране партнёра — его строки.
5. **Тест.** `pb-test-cabinet.mjs`: хит увеличивает счётчик дня; подрядчик не видит чужих строк;
   гость не пишет мимо маршрута.

Выкладка — хуки и миграция по `docs/DEPLOY.md` (свежий master, тест с `--hooksDir`, сверка md5).

## Как сделано (14.11.2026, выложено)

Схема смешанная — решение Никиты 14.11:

| Строка | Откуда | Как попадает в базу |
| --- | --- | --- |
| Переходы, посетители | Метрика, счётчик 113797542, `ym:pv:URLPath` по дням | крон `wed-stats-metrika` раз в час (вчера и сегодня); досчёт — `POST /api/wed/mod/stats-sync { days }` |
| Откуда пришли | Метрика, заходы, начавшиеся с карточки (`ym:s:startURLPath` × `ym:s:lastTrafficSource`) | тот же крон |
| Избранное | свой счётчик: сердце `.save` → `navigator.sendBeacon('/api/wed/hit')` (`src/lib/favorites.ts`) | хук `hit`, +1 к дню; боты и чужие сайты не считаются |
| Заявки | `leads` (связь с карточкой) | на лету, без копии |

- Коллекция `card_stats` (миграция `1762900000`): строка «карточка × день по Москве». Пишет только хук; подрядчик читает свои карточки, модератор — всё.
- Хук — `pb/pb_hooks/lib/stats.js`; маршруты — `GET /api/wed/my-stats?days=7|30|90` (подрядчик), `GET /api/wed/mod/stats` (модератор).
- Экраны: кабинет `/profi/moi/statistika/` (вкладка «Статистика» на месте «Помощи», «Помощь» — строкой в «Профиле»), админка `/profi/admin/statistika/` (в меню ПК; на телефоне — плашка в «Сводке»). Общая отрисовка — `src/lib/stats-ui.ts`, стили — `base.css` (`.st-*`), цвет графика — токен `--adm-chart`.
- Пусто и ноль — разное: до первого дня счёта (`since`) график не рисуется, строка пишет «Считаем с …».
- `METRIKA_TOKEN` — в `/srv/wedsecrets-pb/.env`. Сейчас там токен аккаунта аналитики (шире, чем нужно: запись в Метрику, Вебмастер, Директ) — заменить на токен только `metrika:read` из отдельного приложения.
- Ограничения: Метрика не видит посетителей с блокировщиком и считает визиты самого подрядчика на свою страницу.
