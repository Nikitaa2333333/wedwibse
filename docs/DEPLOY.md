## Хостинг и деплой (боевой сервер, с 01.09.2026)

Сайт живёт на **облачном VPS Timeweb**, домен **wed-secrets.ru** (регистратор
reg.ru, NS остались регруйными). На своём домене сайт живёт в корне, `base` всегда `/`.
Общая процедура (новый сервер, другой проект, SSL, зеркала, разбор поломок) —
в скилле `timeweb-vps-deploy`. Здесь только конкретика этого проекта.

**Обновление сайта — только пушем в master.** [deploy.yml](.github/workflows/deploy.yml)
собирает на раннере и заливает `rsync --delete` под пользователем `deploy`,
примерно минута от пуша до сайта. Руками на сервер ничего не копировать:
следующий деплой всё равно перезатрёт, а права на файлы сломаются
(заливка под root делает файлы недоступными для `deploy`).

**Сборка сайта на сервере не идёт** — это осознанно: 2 ГБ RAM тратятся
на отдачу статики, а не на `npm ci`. Node 22 на сервере при этом стоит —
под конвейер материалов (`/srv/wed-research`), не под сайт.

**Ловушка: деплой «висит» на Rsync (12.10.2026, закрыто, не повторять).**
Три деплоя подряд стояли на шаге «Rsync dist to server» часами, без единой
строки в логе; 10.10 тот же шаг шёл 18 секунд. Сервер был в порядке
(диск 41 %, нагрузка низкая, SSH пускал) — виноваты двое вместе:
- **Медленный канал GitHub → VPS** (~37 КБ/с в тот день): раннер за рубежом,
  сервер в России; скорость между ними от нас не зависит и может упасть
  в любой день.
- **rsync без `--checksum` гонял весь сайт.** Раннер каждый раз свежий,
  у всех ~11 тыс. файлов (2 ГБ, в основном пережатые картинки) новое
  время изменения — rsync считал каждый «изменённым» и обменивался
  блочными суммами по всему объёму. На быстром канале незаметно,
  на медленном — 7 минут и больше.

Что стоит в `deploy.yml` теперь и **не убирать**: `rsync --checksum`
(сравнение по содержимому на сервере, по сети — только изменившееся),
`--timeout=60` и `ConnectTimeout`/`ServerAliveInterval` у ssh, лимиты
`timeout-minutes` у шагов, отдельный шаг «Check SSH to server» (порт 22,
`ssh -v`, `df -h`, `uptime`). Деплой висит или красный — сначала лог
этого шага: там видно, жив ли сервер, а не гадать вслепую. Из облачной
сессии Claude сайт и сервер не открываются (сеть закрыта) — проверять
только по логам GitHub Actions.

**Сайт открыт для поисковиков с 20.10.2026** (`SITE_INDEXABLE: 'true'`
в `deploy.yml`, карта сайта — `scripts/sitemap.mjs`, слои и статус — `docs/seo/SEO.md`,
раздел 5). Значит, всё, что попадает в `master`, видит поиск: прототип,
кабинет, служебная или черновая страница обязана ставить
`<meta name="robots" content="noindex">` в `<head>` — иначе уйдёт в выдачу.


## Заливка хуков PocketBase на сервер

- **Хуки на сервер — только с только что подтянутого master.** Над кабинетом
  работают несколько чатов параллельно, и каждый заливает хуки сам. 03.11
  `cabinet.js` из ветки, отставшей на пару коммитов, затёр на сервере
  выложенные минутой раньше фото с Яндекс Диска (вернули через 3 минуты).
  Перед `scp` хуков: `git fetch` → перебазироваться → тесты → заливка; после —
  сверить md5 файлов сервера с локальными.
