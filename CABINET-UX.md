# Кабинет подрядчика — правила вида и поведения (20.10.2026)

Заказ Никиты: «минимализм, без плашки в плашке, быстро, как лучшие кабинеты
мира, mobile-first, с прицелом на бэкенд». Здесь — разбор образцов и правила,
по которым собран кабинет `/profi/kabinet/`. Решения второго этапа —
`CABINET.md`, трекер — `STAGE2.md`, дизайн-система — `DESIGN.md` §10.

## 1. На кого смотрели

| Кабинет | Что берём |
| --- | --- |
| **Airbnb, кабинет хозяина** (создание объявления) | Карточка заводится ШАГАМИ, один вопрос на экран, прогресс сверху, «сохранить и выйти» в любой момент. Правка готового объявления — список разделов, каждый открывается своим экраном. Главный образец: у нас та же задача — завести витрину с фото, текстом и ценами. |
| **Яндекс Метрика / Директ** (мобильные) | Сводка цифрами первым экраном, детали — по нажатию; статус объекта (кампании, счётчика) — одним словом и одним цветом; список объектов — строками, не карточками с полями. |
| **Stripe Dashboard** | Одна плотность на всех экранах; статус — бейдж из одного слова; действия справа строкой, не блоком; пустое состояние говорит, что сделать дальше. |
| **Telegram** (ввод текста) | Форматирование прямо в тексте: выделил — жирный, список, ссылка. Нет отдельных полей «заголовок» и «текст», человек пишет как в мессенджере. |
| **Notion** | Текст — блоками, блок тянется и переставляется; структура документа видна сразу. |
| **Linear** | Скорость: ничего не ждёт сервера, состояние меняется мгновенно, сервер догоняет; на экране только то, что нужно для действия. |

## 2. Правила

1. **Одна плашка — одна сущность.** Карточка в списке = одна плашка, внутри
   ничего не обрамляется второй рамкой (`DESIGN.md` §2, правило 20.10). Статус
   и пояснение — строкой текста, не вложенным блоком.
2. **Список объектов — строками.** Фото 72px, имя, строка статуса, справа
   стрелка. Никаких полей и кнопок внутри строки: действия — на экране объекта.
3. **Первый экран — сводка, детали по нажатию.** Главная кабинета: карточки
   и что с ними происходит. Анкета: разделы с состоянием («9 из 50 фото»,
   «5 из 8 вопросов»), заполнение — на экране раздела.
4. **Один экран — одна задача.** Раздел анкеты открывается своим экраном:
   заголовок, строка «Сохранено», содержимое, кнопка «Готово». На телефоне
   это единственный способ не превращать анкету в полотно.
5. **Статус — одно слово, один цвет.** Черновик / На проверке / Вернули /
   На сайте. Тёмная плашка только у состояний, требующих действия («Вернули»)
   или достигнутых («На сайте»).
6. **Текст пишут как в мессенджере.** Раздел = один блок текста. Первая
   строка — заголовок, строки с «—» или «•» — список, пустая строка —
   новый абзац. Это ровно `StorySection` (`title`, `text[]`, `list[]`) —
   сервер разбирает блок без разметки, вёрстка карточки не меняется.
7. **Структура предложена заранее.** Для каждой категории — готовый набор
   разделов с подсказками (`src/data/profi-structures.ts`), собранный из
   настоящих карточек каталога. Кнопка «Взять за основу» ставит заголовки,
   человек дописывает. Свои разделы — добавить, лишние — удалить.
8. **Фото: первое — обложка, порядок — пальцем.** Сетка 3 в ряд, счётчик
   «9 из 50», загрузка с телефона или ссылкой на Яндекс.Диск. Без подписей
   к кадрам: описание живёт в тексте.
9. **Скорость.** Автосохранение без кнопки; всё, что можно, меняется на
   экране сразу (чип, галочка, порядок фото), сервер догоняет. Ни одного
   модального окна «Вы уверены?» в рутине — отмена вместо подтверждения.
10. **Белая бумага.** Кабинет — рабочий инструмент: белый фон, нейтральные
    плашки, Onest, без антиквы. Крем остаётся сайту и промо.
11. **ПК — та же схема, шире.** Меню слева (рельс `BottomDock`), контент
    в колонке 720px; разделы анкеты на ПК те же экраны, не «всё на одной
    странице».

## 3. Схема данных, на которую ляжет бэкенд

- Карточка (`revisions.data`): `{ name, category, slug, story: StorySection[],
  answers: Record<filterKey, value[]>, tariffs[], photos: string[] (порядок =
  порядок показа, [0] — обложка), contacts }`.
- Блок текста в кабинете → `StorySection`: первая строка → `title`,
  строки «—»/«•» → `list[]`, остальное → `text[]` по пустым строкам.
- Прогресс раздела считается на клиенте из тех же данных, что и у сервера
  (`filled` в `profi-demo.ts` — заглушка той же формулы).
- Структуры (`profi-structures.ts`) — шаблон только для первого заполнения,
  в данных карточки не хранятся.

## 4. Где смотреть референсы (проверено 20.10.2026)

Никита: «не по памяти, а зайти и посмотреть». Что реально открывается из
облачной сессии:

- **Mobbin** — через браузер отдаёт пустую страницу, но `curl` страниц
  разделов (`mobbin.com/explore/mobile/screens/edit`,
  `…/flows/editing-updating`, `…/flows/adding-creating`,
  `…/screens?app=airbnb`) возвращает HTML со ссылками на экраны, а сами
  картинки лежат открыто на `bytescale.mobbin.com`. Скрипт
  `scripts/mobbin-refs.sh` качает и собирает листы в `research/refs/`.
- **Page Flows, Nicelydone** — только витрина, экраны за входом.
- **UX Archive** — закрыт (403), **App Store** — Никита попросил не брать.

Что взяли с первого листа (разделы «Edit», «Editing/updating», «Adding»):
- экран правки — это список строк «название · значение · стрелка», без
  плашек; поле редактируется на своём экране или в шторке;
- одно действие на экран, кнопка действия одна и внизу;
- серый вторичный текст есть везде — у кабинета он допустим;
- цветной акцент один, на действии и активном состоянии, остальное
  чёрно-белое;
- чипы мелкие (32–36px), текст 15–16px, заголовок экрана 22–28px —
  плотность в два раза выше, чем у сайта для пар.

## 5. Админка — устройство Яндекс Метрики и Директа (24.10.2026)

Никита: «точь-в-точь как Метрика и Директ: левое меню, шапка, вкладки,
таблица; шрифт интерфейса — Inter»; первая версия (мелко, без иерархии,
только модерация) отвергнута. Размеры сняты с живых страниц Метрики
и Директа (computed style) и лежат токенами `--adm-*` в `global.css`.

- Адрес — `/profi/admin/` (noindex), оболочка — `components/admin/AdminShell.astro`,
  стили — `components/admin/admin.css`, значки — `AdminIcon.astro` (линия 1.6),
  поведение таблиц (сортировка, поиск, вкладки, выбор строк, тёмная панель
  действий) — `lib/admin-table.ts`, один раз на все экраны.
- Метрика: поле `#eff2f7`, белые карточки r20 с полями 28/36, левое меню
  14/20 вес 500 с тонкими значками, активный пункт — белая плашка 36 px r12,
  заголовок экрана 24/32 вес 500, карточки 20/28, цифры 24/32; полоса периода
  «Сегодня / Вчера / Неделя / Месяц / Квартал».
- Директ: вкладки 14 вес 500 высотой 48 с подчёркиванием, строка инструментов
  (поиск, выпадашки), таблица — шапка 44, строка 14/20, подстрока 12/16
  со ссылками «Разобрать / На сайте», строка «Итого», чекбоксы и тёмная
  полоса массовых действий внизу; синяя основная кнопка `#2556ff` r10.
- Вторичный текст сине-серый, как у Метрики, — осознанное исключение из
  правила «без серого» (Никита просил серый вторичный ещё 20.10).

Разделы (24.10, после разбора с Никитой — только основа, без мусора):
Сводка · Заявки · Модерация · Карточки · (отдельно внизу) Жалобы.

**Заявки = новые партнёры** (подрядчики и площадки, которые завели учётку
и заполняют анкету), а не обращения невест — это главное в админке. На
сводке они крупно сверху: кто отправил анкету (ждёт решения, срок 24 ч) и
кто бросил черновик (звоним или пишем). Экран заявки: что заполнено
(чипы), текст и фото анкеты, «Связаться» (звонок, Telegram, почта —
открываются у модератора, сайт сам не пишет), готовое напоминание для
черновика — копируется, а не отправляется, комментарии команды (подрядчик
не видит), история, решение: одобрить и опубликовать / вернуть с причиной /
отклонить. Данные — `data/partner-demo.ts`. Обращения невест (форма → `leads`)
вернутся отдельным разделом, когда форму подключат к базе. «Что поменялось»
в модерации — чипами; красное время — только когда до срока 24 ч осталось
меньше 4 часов. Галочки — свои (`.a-check`), не системные. Меню текстом без значков
(как в Директе), счётчики цветом: модерация синим, заявки зелёным, жалобы
красным. Переходы без перезагрузки — `ClientRouter` Astro, скрипты страниц
вешаются на `astro:page-load`.

**Правило: в админке и кабинете нет выдуманных цифр.** Показываем только
то, что будет настоящим: правки (`revisions`), заявки (`leads`), жалобы,
карточки и чего в них не хватает (фото из 50, текст, цена, контакты).
Просмотры — в Яндекс Метрике (в кабинете подрядчика — через её API по
адресу карточки); открытия контактов и избранное — считает наш сервер.
Пока подсчёт не подключён — «нет данных», не число. Отказались: график
заявок, «заполнена на N %», просмотры и конверсии в таблицах, разделы
«Пилот» (стал колонкой «Владелец» в «Карточках»), «Подрядчики», «Интерес»,
«Сверка с таблицей», «Настройки», «Деньги» — вернутся, когда будут нужны.
Три полосы правок (§12 CABINET.md) в интерфейс не выносим до решения Евгения:
вкладки «На проверке / Проверено». Сверху каждой страницы — честная
плашка «Прототип: правки, заявки, жалобы — примеры».

Приёмы других админок внутри модерации: решение карточкой справа
(Zendesk), текст «Изменения / Было / Стало» и свёрнутые неизменённые абзацы
(GitHub), горячие клавиши A / R / J / K и «Отменить» 5 секунд, затем
следующая правка (Gmail, Linear), очередь по сроку — дольше ждущий выше.
